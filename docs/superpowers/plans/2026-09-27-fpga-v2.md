## 1. 何を作るか

**FPGA (PERIDOT-Air) の上に、mruby のバイトコード (`.mrb`) を機械語として直接実行する CPU を作る。それを核にして、mruby ネイティブのマイコンボードとして実機で動かす。**

- **使い方は R2P2 と同じ。** 使う人から見ると、R2P2 (Raspberry Pi Pico の上の PicoRuby) と同じように使える板である。
  電源を入れると起動し、shell が上がり、app を自動で走らせ、ピンを mruby ソースコードで操る
- **中身が違う。** ソフト CPU (Nios II / RISC-V) で mruby の VM を回すのではない。CPU そのものが mruby の命令 (RITE0400、ops.h の 119 命令) を実行する (issue #4)
- **ねらい (issue #4):** 制御の小さなプログラムを、確定した短い遅延でピンに反映させる

## 2. 完成した板の振る舞い (使う人から見て)

| 場面 | 振る舞い | 正本 (同じにする相手) |
|---|---|---|
| 電源投入 | EPCQ から bitstream を読み、起動の像を SDRAM へ写す。firmware が `mrb_open` と同じ初期化をし、R2P2 の起動 (`picoruby-bin-r2p2` の app.rb、`Shell.bootstrap`) を走らせる。`/home/app` があれば自動で実行し、無ければ shell が上がる | R2P2 |
| コンソール | UART。shell のプロンプト `$>` と、puts / p の出力が出る。経路 (I/O ピン + USB-UART の変換) は板の資料で確かめる (V5) | R2P2 のコンソール |
| shell とコマンド | R2P2 の shell (`picoruby-shell` の mrblib) と、ls、cat、cp、rm、mkdir、free、taskstat などのコマンド (build の時に `.mrb` にしたもの) を、そのまま動かす | `picoruby-shell` |
| ファイル | EPCQ の空いた所に littlefs を置く (`picoruby-vfs` と `picoruby-littlefs`。C の所は firmware と flash の mmio) | R2P2 |
| プログラムの入れ方 | host の mrbc で `.mrb` にして送る。host の道具は `rake fpga:upload` / `run` / `reboot` で、`rake rp2040:*` と同じ形。**板の上ではコンパイルしない** (user が決めた、2026-09-27) | harness の `.mrb` を送る既定 |
| ピン | PicoRuby の gem の API をそのまま使う (GPIO、PWM、UART、I2C、SPI、IRQ、タイマー)。LED 2、I/O 28 (3.3V) | PicoRuby の gem |
| 並行と時間 | Task (mruby-task の scheduler)、sleep_ms、割り込み。回路の速い道は、決まったサイクル数でピンに届く | mruby-task、issue #4 |
| 範囲外 | irb、板の上での `.rb` の実行、`sandbox.compile` と eval、RP2 にしか無いもの (PIO、USB CDC、BOOTSEL、WiFi / BLE) | — |

### 2.1 代表の動作: Lチカ (GPIO のオンとオフ)

完成した板で必ず動く最初の例。R2P2 と同じ mruby ソースコードで書く (v1 の `$LED` のグローバル変数ではない)。

```ruby
led = GPIO.new(LED_PIN, GPIO::OUT)   # LED_PIN は板のモデルで USER_LED[0] (PIN_105) に当てた番号 (V4 で決める)
loop do
  led.write(1)
  sleep_ms 500
  led.write(0)
  sleep_ms 500
end
```

**層ごとの道筋 (どれも正本を写す):**
1. **入れる:** host の mrbc で `.mrb` にし、`rake fpga:upload` で littlefs の `/home/app` に置く。電源投入で R2P2 の起動が自動で走らせる
2. **`GPIO.new`:** `picoruby-gpio` の mrblib `gpio.rb` をそのまま使う。中で raise、attr_reader、case、`&` を使う
   - C の所 (`src/mruby/gpio.c` の `_init`、`set_dir_at` ほか) を firmware に写す
   - port の関数 (`ports/rp2040/gpio.c` の形) は、mmio の GPIO のレジスタへの書き込みにする
3. **`led.write(1)`:** 同じ道で mmio の OUT レジスタに書く。RTL の GPIO の回路から USER_LED のピンに届く。回路の中は決まったサイクル数
4. **`sleep_ms`:** `picoruby-machine` の C を firmware に写す。タイマーの mmio と Task の scheduler で待ち、tick の割り込みで起きる

**確かめる所:**

| 条件 | 何を比べるか |
|---|---|
| M1 | ref の板のモデルが記録するピンの変化の列が、host (posix の port に同じ板のモデルを付けたもの) と同じ |
| M2 | RTL のシミュレーションのピンの列が ref と同じ |
| M4 | ボードエミュレーターで、電源投入から `/home/app` が自動で走り、100 MHz の時刻で 500 ms ごとに反転する |
| M5 | 実機の LED が点滅するのを目視する |

**要るもの:** Lチカに要るのは、例外、attr、定数、Integer の演算、Task と時間、gem の mrblib をそのまま使うこと。
よって V2 の全段 (S4 の例外、S7 の gem と Task) の後で ref の上で動く。その時点を V2 の完成を目で見る節目にする。

## 4. 意味の契約

- **mruby の設定:** PicoRuby の組み込みの build と同じ (`MRB_INT64`、`MRB_NO_BOXING`、`MRB_UTF8_STRING`、`MRB_CONSTRAINED_BASELINE_PROFILE`)
- **正本:** mruby と PicoRuby の C と mrblib (`vendor/picoruby/mrbgems/picoruby-mruby/lib/mruby/`、各 gem、確保は `picoruby-machine/lib/estalloc/`)。
  基準は host の PicoRuby (`build/picoruby-fpga/host/bin/picoruby`) の出力
- **回路と firmware と mrblib の分け方:**
  - 回路: 毎命令の速い道
  - firmware: vm.c の遅い道、class.c / gc.c / variable.c / symbol.c / load.c、C で書いたメソッド、gem の C、確保 (estalloc)
  - mrblib: 変えない
- **違えるのは資源と回路の都合だけ**で、全部 [乖離表](../../fpga-v2-deviations.md) に載せる。
  GC の「1 step で 1 周」は立ち上げのための一時の乖離で、完成形では gc.c の incremental を写す。止まる GC は、確定した短い遅延と両立しないため

## 決めたこと (user と 2026-09-27)

- **クロックは 100 MHz をねらう。** 設計の目標は 100 MHz (水晶 50 MHz を PLL で2倍)。**50 MHz は最初に板で動かす時の足場にすぎず、目標ではない。**
  各段の回路は 100 MHz で閉じる前提で段を切る (1 段 1 演算、M9K は同期読み、長い演算は多サイクル)。本当の Fmax は Quartus のタイミング解析で決まる
- **Integer は 64bit の意味 (R2P2 と同じ `MRB_INT64`) を、32bit の回路で計算する。** 下位・上位の2回に分け、桁上げでつなぐ (32bit のマイコンの `long long` と同じ)。
  桁あふれの RangeError も mruby と同じ
- **ポインタ (番地) は 32bit 以下。** SDRAM は 32 MB なので語の番地は 25bit 程度で足りる。整数の幅とポインタの幅は分ける

## 全段の決まり

- **段の頭に表を書く:** 変える意味 → 直す test と表 → oracle (host の PicoRuby と比べる対象) → fuzz が届く所 (要約の stat の名前、0 でないこと) → **資源の関所** (下) の見込み。流してから直さない
- **資源の関所 (毎段):** `rake fpga:synth` (V0 で作る) が yosys の `synth_intel -family cycloneiv` の数 (LE の代わりの lcell、M9K、乗算器) と、
  組み合わせの段数 (yosys `ltp`、100 MHz の目安) を出す。段ごとに予算の表と比べ、超えたら段を終えない。Quartus の fit とタイミングが取れたらそちらを正にする
- **正しさの関所 (毎段):** oracle (host の PicoRuby の出力) = 参照 v2 (`tools/fpga/v2/ref.rb`) の出力 = コアのトレース。参照とコアの一致だけでは段を終えない
- **設計しない、写す。** 正本 (mruby と PicoRuby の C と mrblib) を写す。違えるのは資源と回路の都合だけで、乖離表に載せる。
  違いが出たら、まず写し元の C と並べて違いを列挙する (bisect や 1 件ずつの直しから入らない)
- **置き換えたら古い版を残さない** (CLAUDE.md)。v2 の部品が v1 の部品を置き換える commit で v1 を消す。戻すのは git
- 用語: mruby ソースコード (コアか PicoRuby の VM で走る .rb) と Ruby コード (CRuby で走る道具とテスト) を呼び分ける
- 重い rake は同じ worktree で1つずつ。並べられる所は FPGA_JOBS で並べる

### 再発を止める仕組み (機械で強制する)

v2 は一度、mruby の C を見ずに記憶と自前の設計で書き、壊れたら直すを繰り返した (86921ce の GC、記録を見よ)。これを機械で止める。

| 失敗の型 | 止め方 | 強制するもの |
|---|---|---|
| 記憶で書く | ref の命令、firmware の def、layout.rb の field ごとに写し元を関数名で書く。形は `# C: <file> <関数 / CASE / struct.field>`、対応が無いものは `# C: none (D<nn>)`。行番号では書かない | `inventory_test`: 付いていない、関数がその file に無い、D 番号が乖離表に無い、のどれかで fail |
| 状態を CRuby の中に隠す | 機械の状態は mruby の struct の形でメモリに置く (`mrb_state` / `mrb_context` / `mrb_callinfo` / `mrb_gc`)。ref の CRuby 側に置けるのは、回路のレジスタと cache と定数のポインタだけで、一覧にする | `ref_test`: 一覧に無い instance 変数があれば fail |
| 範囲が後から出る | 棚卸しの表を生成する。host の reflection = C の走査 ∪ mrblib の走査、を突き合わせる | `rake fpga:v2:inventory` が commit と違う、または 3 者が食い違えば fail |
| 独自の設計 | [乖離表](../../fpga-v2-deviations.md) に無い違いは不具合 | 段の完了の条件 |
| 1 件ずつ直す | 進みは accept の assert ごとの表で見る | 段ごとの記録に数を貼る |
| 物差しを緩める | 範囲外は assert 単位。理由は閉じた一覧から選び、D 番号に結ぶ。理由は機械で確かめる | `accept_test`: 範囲内の数が減る、または乖離表を変えずに範囲外を足すと fail |
| 検査が弱い | estalloc は C の .so と Fiddle で比べる (64bit)。GC は小さいヒープで accept 全体を回し、stress は一部で回す | `rake test:fpga`、`fpga:v2:accept` |

## V1 仕様 (spec §10 を v2 に書き直す。コードは書かない)

決めて表にするもの (mruby のソースと照らし、行ごとに vm.c / class.c などの出どころを書く):

| 項目 | 決めること |
|---|---|
| 値 | レジスタ 1 本の表し方 (tag と 64bit の値を M9K の ×36 の2語に置く案)。即値 (nil true false Integer Symbol Float?) とヒープの参照。mruby の MRB_NO_BOXING と見える意味を同じに |
| 命令の取り出し | `.mrb` の irep を SDRAM に置き、命令の cache からバイト単位で読む。可変長 (Z B BB BBB BS BSS S W と EXT1〜3) のデコードを 100 MHz で回す段の切り方 |
| クラスとメソッド | mruby と同じく実行時に定義する (OP_CLASS / MODULE / TDEF / SDEF / ALIAS / UNDEF / SCLASS)。クラスはヒープの RClass、メソッド表はクラスごとのハッシュ表、探索の cache (グローバルなメソッドの cache、M9K)。特異クラス、include (iclass)、prepend、method_missing、BasicObject |
| シンボル | 実行時に intern する表 (ヒープのハッシュ表)。`.mrb` の syms は読み込み時に intern |
| ヒープと GC | 動かない GC (mruby と同じ mark & sweep) にして object_id を mruby と同じにする。SDRAM に置き、データの cache。GC の段の切り方 |
| 例外 | コアのエラー (スタック、ヒープ、未定義の定数、LocalJumpError) も mruby と同じ例外にする。rescue の有無で振る舞いを変えない |
| C の所 | mruby の core の C (array.c string.c hash.c numeric.c class.c kernel.c ...) と PicoRuby の gem の C を、回路の primitive と、コアで走る mruby ソースコードのどちらにするかの表 (速さの要る所だけ回路) |
| Float | mruby ソースコードの soft-float (IEEE 754 double を 32bit の Integer の演算で)。数の文字列化も mruby ソースコード |
| デバイス | GPIO UART PWM ADC I2C SPI タイマー watchdog を mmio で。gem の mrblib はそのまま、C の所だけ |
| 資源 | 上の予算の表を部品ごとに割り振る |
| 板のモデル (V0 で分かった) | host の oracle が device のプログラムの基準になるよう、host (posix の port) と FPGA (mmio) が同じ板のモデルを持つ。upstream の posix の port は IRQ の `register_gpio` を raise し、i2c・spi・watchdog・pio は port が無い。harness の port (firmware-patches か build_config の overlay) で仮想の板を作り、刺激 (stim) を両方に入れる |
| I/O のグローバル変数 (V0 で分かった) | v1 の `$LED` `$BUTTON` (グローバル変数を I/O のポートにする) は PicoRuby に無い。v2 では持たず、LED やボタンは GPIO の gem で。corpus も直す |

#### S6 記憶の管理を写す (estalloc と gc.c)
- **arena:** S2 の arena の列のとおりに、回路も firmware も restore する。`mrb_gc.arena` はメモリにあり、溢れたら gc.c の `gc_arena_keep` のとおり広げる
- **collecting の間:** 確保は ref が例外にする (gc.c の `collecting` の検査の写し)
- **firmware:**
  - `estalloc.rb`: init / malloc / free / realloc / permalloc を写す。ポインタ幅で切り替えられる形にする
  - `gc.rb`: gc.c から写す。`malloc_increase` は `mrb_realloc` から写す

- **確かめ:**

  - accept の表全体が、普通と小さいヒープで変わらない
  - stress (N 回の確保ごとに GC、N は S1 の steps/s から決めて書く) を programs、fuzz、決めた一部の file で回す
  - programs と fuzz が小さいヒープで `gc` > 0

## V5 実機への道具 (M5)

- Quartus で fit とタイミング (Linux の VM が要る。この環境では回せない)。100 MHz で閉じなければ、段を切り直す所を関所の表から探す

## 見つけたこと

- 組み直し (レビューで分かった正本の事実):
  - この PicoRuby の分岐の gc.c は full GC ではない。`mrb_obj_alloc_core` が確保ごとに `gc_debt` を数えて incremental に進め、
    既定は generational (`mrb_gc_init`)。scheduler の `auto_step` / `debt_limit` もある
  - arena の restore は vm.c の仕事で、`mrb_vm_exec` の入口で save し、命令ごと (ARRAY、HASH、LAMBDA、CLASS、DEF、RETURN ほか) に restore する。
    写す関数 (gc.c など) の中には無い
  - `mark_context_stack` は、使っていないスタックを nil で消す。vm.c の `stack_clear` も同じ
  - host の PicoRuby は `picoruby a.rb,b.rb,c.rb` で複数の file を 1 本として走らせる。mruby の test/t は、driver.c の `t_print` と
    `_str_match?` を足せば host で走る (47 本のうち 36 本が KO も Crash も 0)
  - heap page の大きさは profile で違う (posix の baseline は 1024、組み込みの constrained は 128。`picoruby-mruby/mrbgem.rake`)
  - R2P2 の shell (`picoruby-shell`) は mrblib で、コマンドは build の時に `.mrb` になる。板の上でのコンパイルは irb と `.rb` の実行だけ

- V2b: 罠のフレームを nregs の後ろに置くと、`__fpga_sendv` が nregs から並べた呼び出しの窓 (受け手・引数) を上書きする。
  罠は呼び出しの途中なら窓の後ろ (a + n + 2) に置く
- V2b: `f(*a)` は `LOADNIL R; ARYCAT R` になる (R[a] が nil なら splat だけ、vm.c)。SUPER は BB (引数の数は b)
- V2b: 差分ファズの method_missing の到達が 0 だった (定義しても未定義のメソッドを呼んでいない)。呼ぶ文を足すと String#size の抜けが出た。
  表の「到達」を実際の stat で見ないと、通ったことにならない

- V2a: mrbc は `self == y` を EQ ではなく `SSEND :==` にする (受け手が self の時)。firmware は Integer#== などをメソッドとして持ち、
  中では局所変数同士の式 (EQ、ADD の命令) にする。`!=` と `!` もメソッドの呼び出しになるので、探索の罠の中では使わない
- V2a: `while` の中の `return` は RETURN_BLK になる (ブロックでなければ RETURN と同じ、vm.c)
- V2a: ADDILV / SUBILV は R[a] を書き換える (b は整数でない時の呼び出しの作業の枠)。INT_MIN の `%` は `x - (x / y) * y` だと
  桁あふれするので、除算器の余り (`__fpga_rem`、C の %) から floor の剰余を作る

- V0: upstream の picoruby-gpio (`src/mruby/gpio.c` の `pin_num`) が `mrb_get_args("oi")` に `int *` を渡し、MRB_INT64 で 8 バイト書いてスタックを壊す
  (host で "stack smashing detected")。`firmware-patches/gpio-pin-num-mrb-int.patch` で直し、tools の VM と実機の firmware の build で当てる。
  gem の C を全部見た (`mrb_get_args` の "i" に mrb_int でない変数を渡す所) のはここ1か所
- V0: yosys 0.33 の `synth_intel` の M9K の割り当ては実験的で個数が合わない。M9K は割り当て前の記憶 ($mem_v2) から数える。
  yosys は carry chain と DSP を使わないので、段数と LUT の数は加算と乗算で Quartus より大きく出る (乗算は blackbox にする)
- V0: 既存のファイルを Write で上書きしないこと (tools/fpga/oracle.rb を一度上書きし、ref_vm_test の関数を消した。37be099 で戻した)
