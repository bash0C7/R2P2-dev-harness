# FPGA v2 S7-1: Lチカ (計画 §2.1) を ref で通し、host と比べる

[計画 S7](2026-09-27-fpga-v2.md) の最初の段。gem の全体 (picotest、R2P2 のプログラム、accept への追加) は後の段で、ここは Lチカだけ。
乖離表は D100〜D119 を使う ([fpga-v2-deviations.md](../../fpga-v2-deviations.md))。

## 段の表 (全段の決まりの形)

| 項目 | 中身 |
|---|---|
| 変える意味 | GPIO (picoruby-gpio の C)、`sleep_ms` (mruby-task の C)、mruby-task の scheduler の最小 (main task 1 つ、tick、sleep の待ち) を firmware に写す。gem の mrblib (`gpio.rb`) はそのまま像に入れる。port の関数は mmio。ref に板のモデル (GPIO、タイマー、tick の割り込み) を置く。host の posix の port に同じ板のモデルを firmware-patches で入れる |
| 直す test と表 | `board_test.rb` (板のモデルのレジスタとピンの列)、firmware_test (注釈、L:、SEND 先、aspec)、ref_test (CRuby 側の変数の一覧に `@board`)、乖離表 D100〜D105 |
| oracle | host の PicoRuby (`build/picoruby-fpga`、patch 入り) が出すピンの変化の列 (時刻, pin, 値) とコンソールの出力 |
| fuzz が届く所 | fuzz と programs は GPIO と sleep を使わない (起動がプログラムごとに main task を作って消す所だけ通る)。板のプログラムは ref の stat `mmio` (mmio の読み書きの数) が 0 より大きい |
| 資源の関所 | 回路は無い。firmware の `.mrb` のバイトと、Lチカの ref の命令の数を記録する |

## 板のモデル (V4 で PERIDOT-Air のピンに当てる)

時刻は tick (`MRB_TICK_UNIT` = 4 ms、host の build_config と同じ) の数で数える。**全 task が待つ時 (scheduler の idle と、HAL の止まる sleep) だけ 1 tick 進む。命令は時間を使わない** (D100)。

| 番地 (layout.rb) | 名前 | 読む | 書く |
|---|---|---|---|
| 0x0400_0000 | `MMIO_GPIO_OUT` | 出力の latch (bit n = pin n) | latch |
| 0x0400_0004 | `MMIO_GPIO_DIR` | 向き (1 = 出力) | 向き |
| 0x0400_0008 | `MMIO_GPIO_IN` | ピンの値 | — |
| 0x0400_000C | `MMIO_GPIO_PULL_UP` | pull up の bit | pull up |
| 0x0400_0010 | `MMIO_GPIO_PULL_DOWN` | pull down の bit | pull down |
| 0x0400_0020 | `MMIO_TIMER_TICKS` | 電源投入からの tick の数 (下 32bit) | — |
| 0x0400_0024 | `MMIO_WFI` | — | 割り込みを待つ: 次の tick まで時刻を進め、tick の割り込みを立てる |
| 0x0400_0028 | `MMIO_IRQ` | 立っている割り込み (bit 0 = tick) | 1 を書いた bit を下ろす |

- ピンは 32 本 (0〜31)。ピンの値 = 出力なら latch、入力なら pull down の時 0、ほかは 1 (浮いた入力は 1。upstream の posix の `GPIO_read` と同じ)。32 以上のピンは無い (書いても変わらず、読むと 1) (D101)
- `GPIO_init` は rp2040 の `gpio_init` と同じく入力にして latch を 0 にする
- LED のピンは板のモデルの定数 `Board::LED_PIN` = 28 (I/O 0〜27 の次。V4 で USER_LED[0] (PIN_105) に当てる)
- SDRAM は 0〜0x01FF_FFFF (32 MB)。mmio はその外なので、ref は `__fpga_ld32` / `__fpga_st32` の番地で分ける

## 比べ方

`loop` は終わらないので、比べるのは仮想の時刻で区切ったピンの変化の列 **(時刻 ms, pin, 値)** とコンソールの出力。

- **プログラム:** `fpga/v2/board/*.rb` (Lチカは `blink.rb`、§2.1 と同じ mruby ソースコード)。走らせる時に頭へ `LED_PIN = <Board::LED_PIN>` の 1 行を足す (host と ref で同じ)
- **止め方:** 次の tick の時刻が上限 (既定 2000 ms) を超える所で止める。上限ちょうどの変化までが列に入る
- **host:** firmware-patches の 2 つ (build 中だけ当てる、`rake fpga:picoruby`)
  - `posix-board-clock.patch` (mruby-task の `ports/posix/task_hal.c`): SIGALRM の timer をやめ、`mrb_hal_task_idle_cpu` と `mrb_hal_task_sleep_us` が 1 tick ずつ時刻を進めて `mrb_tick` を呼ぶ。環境変数 `FPGA_BOARD_UNTIL_MS` があれば、その時刻を超える所で exit(0) し、ピンの列を stderr に `pin <ms> <pin> <値>` の行で出す (無ければ上限も列も無い。仮想の時計は同じ)
  - `posix-board-gpio.patch` (picoruby-gpio の `ports/posix/gpio.c`): 上の表の GPIO のレジスタを C の変数で持ち、ピンの値が変わると列に書く
- **ref:** `tools/fpga/v2/board.rb` の `Board` が mmio を受け、ピンの列を持ち、上限で `Ref::Halt` を上げる。ref.rb への hook は `__fpga_ld32` / `__fpga_st32` の番地の分け方だけ
- **道具:** `tools/fpga/v2/pins.rb` (host と ref の列を出して比べる)、`rake fpga:v2:pins` (上限は `rake "fpga:v2:pins[3000]"`)

## 分かっていること

- GPIO のクラスは gem の C (`mrb_define_class_id`) が起動で作るので、起動の像のクラスの表 (`Image::CORE`) に置く。定数は `__fpga_init_gpio` が mrblib の前に置く (mruby は core の mrblib の後に gem の C の init を回すが、見える違いは無い)
- firmware-patches は rp2040 の build にも当たる (`with_firmware_patches`)。posix の port は rp2040 で compile されないので中身は変わらないが、`rake rp2040:build` の入力の hash が変わり 1 回 build し直す

- host の main は `mrc_create_task` の task で走るので `sleep_ms` は task の道 (`sleep_us_impl` の WAITING、tick の単位で起きる)。firmware もプログラムを main task として扱う (D103)
- task の scheduler は GC の根になる (`mrb_task_mark_all`: 各 queue の task の self / result / name と context)。firmware の main task の構造体はヒープ (`__fpga_alloc`) にあり、S6 で根に足す
- 時間切れの切り替え (timeslice) は idle の外で tick が来ないので起きない (D100)。忙しい task を 2 つ並べるプログラムは host でも止まらない (fpga の host の VM だけ。R2P2 の実機の firmware と host のテストの VM は変えない)
