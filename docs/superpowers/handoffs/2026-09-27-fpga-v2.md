## 何を作っているか

FPGA (PERIDOT-Air) の上に mruby のバイトコード (`.mrb`) を直接実行する CPU を作り、それを核にした mruby ネイティブのマイコンボードとして実機で動かす。
使い方は R2P2 と同じ (電源投入 → shell、app の自動実行、ピンを mruby ソースコードで)。代表の動作は GPIO の Lチカ。
完成形と完成の条件 (M1〜M5) は [計画の §1〜§5](../plans/2026-09-27-fpga-v2.md)。当面は M4 (ボードエミュレーター) まで。

- 計画: [plans/2026-09-27-fpga-v2.md](../plans/2026-09-27-fpga-v2.md) (V2 は S0〜S7 に組み直した。順番は S0 → S3 → S1 → S2 → S2b → S2c → S4 → S5 → S6 → S7)
- 設計: [specs/2026-09-27-fpga-v2-core-design.md](../specs/2026-09-27-fpga-v2-core-design.md)
- mruby との違い: [fpga-v2-deviations.md](../../fpga-v2-deviations.md) (ここに無い違いは不具合)
- v1 が外れていた所: [fpga-divergence.md](../../fpga-divergence.md)

## user と決めたこと

- 目標は3つとも: mruby の意味で `.mrb` を実行する / PicoRuby (R2P2) のプログラムが host と同じ出力で動く / PERIDOT-Air に載る
- **100 MHz をねらう** (50 MHz は最初に板で動かす足場で、目標ではない)。64bit の Integer の意味を 32bit の回路で (2 回に分けて計算)
- **板の上ではコンパイルしない。** host の mrbc で `.mrb` にして送る。R2P2 の shell とコマンド (build の時に `.mrb`)、littlefs、app の自動実行は同じにする。irb と eval は範囲外
- **設計しない、写す。** 正本 (mruby と PicoRuby の C と mrblib) を写し、違いは乖離表に載せる。進みは accept の assert ごとの合格数で測る。
  1 件ずつ直す、bisect から入る、はやめる (計画の「再発を止める仕組み」)
- 計画は subagent の敵対的なレビューを通してから出す
- **反復で進める (2026-09-28):** 狭い範囲で mruby のバイトコード → 回路 → 板を通してから広げる。仕掛りを増やさない。実機はまだ無いので、シミュレーションの結果を見える形 (HTML、スクショ) で示す
- 用語 (mruby ソースコード / Ruby コード)、古い版を残さない、vendor は commit しない、Python は書かない、返答は日本語で短く (CLAUDE.md)
- **S5〜S7 の進め方 (2026-09-28):**
  - 参照 (`tools/fpga/v2/ref.rb`) を速くしてよい。意味は変えない。
    - 例: 命令の decode を (iseq, pc) で cache する、Ci の生成を減らす、記憶の読み書きを速くする
    - 理由: array.rb の深い join は C (join_ary) も O(n²) の祖先の走査で、host は native なので一瞬だが、参照は firmware (mruby ソースコード) を CRuby で解釈するので時間がかかる
    - 今の速さは約 12 万命令/秒。この環境の Ruby 3.3.6 は YJIT 無しで build されている
  - S6 は計画を書いて subagent の敵対的なレビューを通したら、user の承認を待たずに実装へ進む。計画とレビューの結果は commit に残す
  - S5 の残り、S6、S7、参照の高速化は、worktree の subagent で並べて進めてよい。merge と検証は main の session がする
  - S7 の Lチカで host と比べる板のモデル (posix の GPIO とタイマー) は firmware-patches (build 中だけ当てる) か build_config の overlay で host の picoruby に入れる。vendor は commit しない

今の状態 (R2):
- **反復で進めている (user、2026-09-28)。** 「mruby のバイトコード → 回路 → 板」の縦の一本を先に通し、反復ごとに広げる (計画の「反復で進める」の節)。仕掛りは 1 本ずつ
- **R2 済 (実機を除く):** `fpga/rtl/rite_core.sv` (+ `rite_rom.sv`)。
  - ROM は mruby の mrblib `kernel.rb` と `fpga/rite/blink.rb` (loop 版) を mrbc した `.mrb` を並べたもの (`tools/fpga/rite_rtl.rb` の `MRBLIB`)。
    回路は mrb_open と同じく先頭の .mrb から読み (load.c の read_irep の形)、実行する。kernel.rb の実行で `Kernel#loop` が定義され (MODULE、EXEC、TDEF、`module_function`)、blink.rb の `loop` はそれを呼ぶ (回路の組み込みではない)
  - SEND / SSEND / SSENDB は、受け手のクラスの祖先の並び (回路の定数) の順にメソッド表 (8 行) を引く。C の関数は GPIO.new、GPIO#write、Kernel#sleep_ms、Module#module_function。無ければ error (method_missing は範囲外)
  - 呼び出しの枠 4 段、irep 8 個、sym 32 個、レジスタ 64 本 (M9K)。Integer は 32bit。ブロックの env は枠が生きている間だけ。可視性は private の印だけ (TDEF は public)
  - `rake fpga:rite:check`: 2000 ms まで host とピンの列が同じ。`rake fpga:sim[rite_core_tb]` / `fpga:sim:icarus[rite_core_tb]` が PASS (+TRACE で実行した命令)。`rake fpga:synth[rite_core]`: 3,033 LE、M9K 1、段数 13 (予算 3,136 LE、段数 13 で余裕はほぼ無い)
  - `rake fpga:rite:build`: Quartus のプロジェクト (top `peridot_air_rite_top`、ROM 2,048 バイト)。**Quartus と実機は未確認 (user は板をまだ持っていない)**
  - `rake fpga:tb` 全体は約 20 分: v1 の peridot_air_top_tb の Icarus のコンパイルが約 17 分 (R2 の前から)
  - 見える形: scratchpad の `rite_view_gen.rb` と `rite_view.html.in` (R2 の形: kernel.rb と blink.rb の両方、ROM の番地で命令を照らす)。道具にするなら rake の task にする

## 再開の手順

- 作業は本体の checkout (`/home/user/R2P2-dev-harness`) でする。`.claude/worktrees/` の worktree で rake を回すと、`fpga:picoruby` が
  vendor の symlink の相対の道で `vendor/picoruby/src/version.c` を見つけられず落ちる
- rake の前に `export PATH=/opt/rbenv/versions/3.3.6/bin:$PATH LANG=C.UTF-8` (LANG が無いと firmware_test が US-ASCII で落ちる)
- 最初に `rake setup` (vendor/picoruby が無ければ clone) と `rake fpga:picoruby` (host の picoruby と mrbc、build/picoruby-fpga)
- 確かめ: `rake test:fpga`、`rake fpga:v2:check`、`rake fpga:v2:fuzz[100,1]`〜`[100,4]`、`rake fpga:v2:accept` (file を絞るなら `rake "fpga:v2:accept[exception module]"` の形)。重いものは 1 本ずつ
- accept の step の上限は file ごと。array は深い join があるので上限を上げないと数が出ない
- `pkill -f` は自分の shell の command 行にも当たって自分を殺す (exit 144)。止めるのは PID で
