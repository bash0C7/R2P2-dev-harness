## 何を作っているか

FPGA (PERIDOT-Air) の上に mruby のバイトコード (`.mrb`) を直接実行する CPU を作り、それを核にした mruby ネイティブのマイコンボードとして実機で動かす。
使い方は R2P2 と同じ (電源投入 → shell、app の自動実行、ピンを mruby ソースコードで)。代表の動作は GPIO の Lチカ。
完成形と完成の条件 (M1〜M5) は [計画の §1〜§5](../plans/2026-09-27-fpga-v2.md)。当面は M4 (ボードエミュレーター) まで。

- 計画: [plans/2026-09-27-fpga-v2.md](../plans/2026-09-27-fpga-v2.md) (V2 は S0〜S7 に組み直した。順番は S0 → S3 → S1 → S2 → S2b → S2c → S4 → S5 → S6 → S7)
- 設計: [specs/2026-09-27-fpga-v2-core-design.md](../specs/2026-09-27-fpga-v2-core-design.md)
- mruby との違い: [fpga-v2-deviations.md](../../fpga-v2-deviations.md) (ここに無い違いは不具合)
- v1 が外れていた所: [fpga-divergence.md](../../fpga-divergence.md)

## user と決めたこと

- 目標は3つとも: mruby の意味で `.mrb` を実行する / PicoRuby (R2P2) のプログラムが host と同じ出力で動く / PERIDOT-Air に載る
- **100 MHz をねらう** (50 MHz は最初に板で動かす足場で、目標ではない)。64bit の Integer の意味を 32bit の回路で (2 回に分けて計算)
- **板の上ではコンパイルしない。** host の mrbc で `.mrb` にして送る。R2P2 の shell とコマンド (build の時に `.mrb`)、littlefs、app の自動実行は同じにする。irb と eval は範囲外
- **設計しない、写す。** 正本 (mruby と PicoRuby の C と mrblib) を写し、違いは乖離表に載せる。進みは accept の assert ごとの合格数で測る。
  1 件ずつ直す、bisect から入る、はやめる (計画の「再発を止める仕組み」)
- 計画は subagent の敵対的なレビューを通してから出す
- **反復で進める (2026-09-28):** 狭い範囲で mruby のバイトコード → 回路 → 板を通してから広げる。仕掛りを増やさない。実機はまだ無いので、シミュレーションの結果を見える形 (HTML、スクショ) で示す
- 用語 (mruby ソースコード / Ruby コード)、古い版を残さない、vendor は commit しない、Python は書かない、返答は日本語で短く (CLAUDE.md)
- **仕事の種類でmodelを分ける (2026-10-11):** 決定論コマンド (rake、build、flash、検出) はhaikuのsubagent、コード修正はsonnetのsubagent、複雑な仕様検討はfableのsubagent、一般的な制御と検討はmainのsession。gitのmutate系 (add / commit / push / gh) はmainが直に叩く
- **S5〜S7 の進め方 (2026-09-28):**
  - 参照 (`tools/fpga/v2/ref.rb`) を速くしてよい。意味は変えない。
    - 例: 命令の decode を (iseq, pc) で cache する、Ci の生成を減らす、記憶の読み書きを速くする
    - 理由: array.rb の深い join は C (join_ary) も O(n²) の祖先の走査で、host は native なので一瞬だが、参照は firmware (mruby ソースコード) を CRuby で解釈するので時間がかかる
    - 今の速さは約 12 万命令/秒。この環境の Ruby 3.3.6 は YJIT 無しで build されている
  - S6 は計画を書いて subagent の敵対的なレビューを通したら、user の承認を待たずに実装へ進む。計画とレビューの結果は commit に残す
  - S5 の残り、S6、S7、参照の高速化は、worktree の subagent で並べて進めてよい。merge と検証は main の session がする
  - S7 の Lチカで host と比べる板のモデル (posix の GPIO とタイマー) は firmware-patches (build 中だけ当てる) か build_config の overlay で host の picoruby に入れる。vendor は commit しない

### Mac での進み (2026-10-10): 合成は通った、書き込みは JTAG で止まっている

- **Quartus:** Apple container (x86-64 Ubuntu 22.04 + Rosetta 2) に Quartus Prime Lite 23.1std.1 を入れた。
  image `r2p2-quartus` (`tools/fpga/container/Dockerfile`)、volume `quartus` (`/opt/quartus`、9.1 GB)。
  Altera の配布はログインが要るので、user が落として `build/quartus-installer/` に置き、`tools/fpga/container/install.sh` で入れる。
  `tools/fpga/container` を PATH に足すと `rake fpga:rite:build` がラッパー (`quartus_sh` / `quartus_cpf`) 経由でそのまま回る
- **合成 (R3):** 4,792 LE / 6,272 (yosys の見積もり 3,994)、メモリ 49,088 bit、ピン 5。50 MHz の setup slack 3.5 ns。ROM は M9K で rom.hex が初期値に入る。
  Quartus Lite は module の見出しの中の `import` を構文エラーにする (Error 10170) ので、`tools/fpga/quartus.rb` が写す時に module の前へ出す。rite の project は rite の 5 file だけ
- **Mac のシミュレーション:** `rake fpga:rite:check` と `fpga:sim[rite_core_tb]` は green。`fpga:sim:icarus[rite_core_tb]` は Icarus 13.0 が rite_core.sv の 12 か所を「明示の cast が要る」で落とす (回路は未変更)
- **板の JTAG:** PERIDOT-Air の micro-B は給電だけ。JTAG は 6P ヘッダー (左列 TDO/TCK/TMS、右列 GND/TDI/3.3V、TCK は板で 1 kΩ pull-down、TDO は pull 無し) を同梱の JTAG-CONN で 10P にして USB-Blaster。
  USER_LED は active high (top の `LED_ACTIVE_LOW = 0` で合う)。JTAG に押すボタンは無い
- **止まっている所:** 手元の USB-Blaster は互換品 (bcdDevice 0x0600)。openFPGALoader v1.1.1 も OpenOCD 0.12 も IDCODE が全部 0 (`TDO is stuck at 0`)。
  ケーブルの両端を入れ替えると TDO が浮いた読め方 (0x00000001 が数個続いて 0) に変わる。FPGA の TAP が応答していない (TCK か TMS が届いていない) 見立て。
  向き (赤線 = ▲ = 1 番、板のロゴの側) と挿し方は確認済み。次は**テスターでケーブル 10 本の導通と、変換基板の 10P の 4 番 (VCC) – 2 番 (GND) が 3.3 V か**を見る。
  駄目なら JTAG アダプターを替える (FT232H / FT2232H を推奨、または RP2040 の Pico + dirtyJtag)
- **USB-Blaster の口の確かめ方 (未実施):** ケーブルを外し、USB-Blaster の 10P で 3 番 (TDO) と 9 番 (TDI) をジャンパーでつなぎ、
  4 番 (VCC) を板の 3.3V、2 番を板の GND へ。`openFPGALoader -c usb-blaster --detect` が 0 以外を読み戻せば口は生きていて、悪いのはケーブルか板の側。
  板の給電を Mac から別系統に移しても結果は同じ (全部 0)。ケーブルを外しても USB-Blaster は認識され、RUN の LED はアクセス中だけ点く

  3. 転送した installer を `build/quartus-installer/` に置き、`tools/fpga/container/install.sh` で Quartus を入れる。`tools/fpga/container` を PATH に足して `rake fpga:rite:build`

  5. 返れば `rake fpga:flash` で R3 を焼き、USER_LED[0] が 500 ms ごとに点滅し USER_LED[1] が消えたままを目で見る
