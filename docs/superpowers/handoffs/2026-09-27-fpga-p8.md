## P8 64bit の Integer: 実装済み、WIP commit (未検証の所あり)

- 作ったのは worktree `/home/user/p8wt` (vendor は main への symlink)。そこで全部のファイルを直してから main の作業ツリーへ写した
  (main と p8wt の違いは計画の md だけ。main の方には P5e の記録の行もある)
- 中身 (詳細は spec §10「64bit の Integer (P8)」と計画の「見つけたこと」の P8):
  - isa.rb `INT_BITS = 64`、`CERR_OVERFLOW = 8`、`OVF_*` (0 plain、1 add、2 sub、3 mul、4 div、5 shift)、命令 `LOADI64` (0xF3)
  - ref_vm.rb: `ovf` / `overflow!` (stat `overflow`)、LOADI32 は符号拡張、シフト、I/O は下の 32bit、トレースの W / O は `%016x`
  - RTL: mrb_core.sv の桁あふれの wire (add / sub / mul / div / neg / addi / subi / shl / shr、`p_ovf`、`o_ovf`、`o_ovf_at`)、
    `f_int` / `f_toi` (bit で組んだ Integer ⇔ double)、`LOADI64` (S_LF1–3 を流用)。Verilator の幅の警告 95 件を全部直した。
    mrb_dev.sv は `rd32` を符号拡張し、TIME_US と TIME_MS は 64bit
  - プレリュード: `Integer#to_s` (負の側で割る)、`String#to_i` (負の側で数え、RangeError)、`**` (in power)、
    Float の `floor` / `ceil` / `truncate` (in rounding) と `round` (Float のまま)、`__core_error` の 7 と 8
  - gems: time.rb は 0x110 を1回で読む、task.rb の `NEVER = 0xFFFFFFFF` (Task.stat は UINT32_MAX)
  - 道具: rite.rb の INT64 の pool (PicoRuby で桁あふれしない形)、rom.rb の LOADI64、compare / displays / oracle / gap / rake の 64bit
  - コーパス: `fpga/corpus/int64.rb` (host picoruby と全行一致、参照と RTL は同じトレース)、`fpga/corpus/mml.rb`
    (音の間隔 500–501ms。32bit では数 ms に詰まっていた)。ref_vm_test の CRUBY_CANNOT に int64 と mml
  - fuzz: LOADI64 の値、pick 25 (64bit の断片、重み 3/28)、`INT64_SYMS`
  - tb: mrb_core_tb に overflow add / addi and loadi64 / overflow div
- p8wt で通ったもの: tb 両シミュレーター PASS、test:fpga 全部 (rom_test の SSEND0 の許可を足した後)、check 39 本 ok、emu ok、
  fuzz seed 1–3 一致 (重みを上げる前)、重みを上げた後の seed 1 一致 (overflow 16 回)
